# Shipway v3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Ship the six user-requested items: instance-level mail (settings + invites + email channels), Microsoft Teams channels, the Cloudflare "always Connected" fix, DNS confirmation in New Project, the cancel-deployment fix, and a real environment-variables editor.

**Architecture:** Same monolith. Server adds migration 0002 (channel type/target), a mail service (nodemailer), abortable git/wait paths, and a richer verify route. Web restyles two surfaces (Env tab, New Project domain card) and adds a Settings → Mail section, all within DESIGN.md v2's existing token/component vocabulary.

**Spec:** `docs/superpowers/specs/2026-08-25-shipway-v3-design.md` (root causes for both bugs are in §2 — trust them, they were verified against the code). **Design authority:** `DESIGN.md` + `PRODUCT.md`.

## Global Constraints
- TypeScript strict; root `npm run typecheck`, `npm run build`, and the full server suite green at every commit.
- DESIGN.md v2 is binding for every visual choice (tokens, Card/CardHeader anatomy, buttons, forms, both themes). No banned patterns; no em dashes in copy.
- Role gates: mail settings + channel CRUD are admin+; reads are member-ok. Every mutating route records an audit event; secrets (SMTP password, channel targets/URLs) never enter audit meta or logs.
- Secrets at rest use `SecretBox` (instance mail password), never returned in API responses (masked like `cloudflare_token`).
- UI tasks verify with real headless-Chrome screenshots in BOTH themes (method: prior task reports; always set SHIPWAY_DATA_DIR + SHIPWAY_APPS_DIR + SHIPWAY_LOGS_DIR into scratch, port ≥8120, kill server + clean up after).
- Conventional commits with the standard trailer.

### Task 1: Cloudflare verify honesty (spec §3 "Cloudflare verify")
**Files:** server/src/routes/cloudflare.ts, server/src/services/cloudflare.ts (FakeDnsClient gains configured-state + a `verifyToken` that reflects it), server/src/app.ts (dns getter: dev mode uses the fake only when credentials exist, else null), server/test/cloudflare-route.test.ts (+cases), web/src/pages/settings/Cloudflare.tsx (three-state UI: Connected / Not connected + reason / Not configured), web/src/api.ts + hooks (verify response shape).
**Behavior:** route returns `{ok, reason}` per spec; settings checked before devMode; blank/whitespace token or zone id → `not_configured`; real API failure → `invalid_token` or `error:<msg>` (never leak the token in the message).
**Tests:** not-configured (empty, whitespace, missing), fake-configured dev path, real client failure mapping (injected fetch), UI states typecheck.
**Gate:** server tests + typecheck + build; screenshots of the three states (light+dark for at least Connected + Not configured).

### Task 2: Cancel deployment, root-cause fix (spec §2 #5, §3 "Cancel deployment")
**Files:** server/src/services/git.ts (GitOps methods take an optional `signal` and pass `cancelSignal` to every execa call — including the archive|tar pipe), server/src/deploy/pipeline.ts (pass `signal` into gitOps calls; make `sleep`/`fetchHttp`/`waitForPort` abortable — `deps.sleep(ms, signal)`, fetch with `AbortSignal.any`-style composition or pass-through, default waitForPort polls with signal checks; log `==> cancel requested` when the signal fires), server/src/deploy/runshell.ts (`forceKillAfterDelay: 5000`), server/src/deploy/queue.ts (expose `isCancelRequested(id)`), server/src/routes/deployments.ts (GET detail + list include `cancelRequested: boolean`), web project Deployments tab + DeploymentLog (optimistic "Canceling…" disabled button + status hint).
**Tests:** cancel during a long fake git fetch aborts within ms (inject a gitOps whose fetch waits on the signal); cancel during health-check sleep returns 'canceled' fast; runshell force-kill option present; queue reports cancelRequested; route shape; existing cancel tests still pass.
**Gate:** full suite; screenshots of the Canceling state.

### Task 3: Instance mail — settings, service, test send (spec §3 "Instance mail")
**Files:** `npm i nodemailer -w server` (+ @types), server/src/services/mailer.ts (`getMailConfig(db, secretBox)`, `sendMail(cfg, {to, subject, text, html?})`, `isMailConfigured`), server/src/routes/mail.ts (GET/PUT /api/settings/mail admin+ with password masking; POST /api/settings/mail/test {to} admin+ → real send, returns {ok, error?}), settings keys `instance_mail` (JSON; password encrypted via SecretBox), audit rows (`mail.configure`, `mail.test`), web/src/pages/settings/Mail.tsx + Settings rail row (Mail, `Mail` icon) between Cloudflare and Team.
**Behavior:** driver 'none' disables everything; 'mailpit' prefills 127.0.0.1:1025 no-auth (reads mailpit_info when present); 'smtp' takes host/port/secure/user/pass/from.
**Tests:** config round-trip w/ encryption at rest + masking; role gates; test-send success/failure via injected transport; driver 'none' → isMailConfigured false.
**Gate:** full suite; screenshots both themes.

### Task 4: Email + Teams delivery channels (spec §3 "Delivery channels")
**Files:** migration 0002 (notification_channels + `type` TEXT NOT NULL DEFAULT 'webhook', `target` TEXT NULL), server/src/services/notify.ts (Teams MessageCard formatter + URL detection; email path via mailer), server/src/services/notifybus.ts (dispatch by channel type), server/src/routes/notifications.ts (create/update accept type+target with validation: webhook/teams require url, email requires a valid address AND configured instance mail — else 400 with a clear message; test-send works per type), web settings/Notifications.tsx (type picker in the Add form, per-type fields + helper copy, channel rows show a type badge).
**Tests:** migration on fresh+upgraded db; Teams payload shape + auto-detection; email channel send via injected mailer; validation matrix; existing webhook behavior unchanged.
**Gate:** full suite; screenshots.

### Task 5: New Project DNS confirmation (spec §3 "New Project DNS")
**Files:** server/src/services/provisioner.ts (report DNS outcome: `{attempted, created, existed, error?}` — do not change failure semantics), server/src/routes/projects.ts (POST response includes `dns`), web/src/pages/ProjectNew.tsx (Domain card: exact record line `A  <slug>.<base_domain>  →  <server_ip>`, live Cloudflare status via the verify hook, warning + "Connect Cloudflare" link when not connected, required "Create anyway (no DNS record)" checkbox to enable Deploy in that case, and a post-create result row showing created/existed/error before navigating).
**Tests:** provisioner returns each outcome; route passes it through; UI typecheck.
**Gate:** full suite; screenshots of connected and not-connected variants.

### Task 6: Environment variables editor (spec §3 "Env editor")
**Files:** web/src/pages/project/EnvEditor.tsx (Table/Raw mode toggle, row editor with add/delete, duplicate-key warning, masking + reveal for secret-looking keys, preserved non-row lines note, one Save), web/src/lib/envparse.ts (`parseEnv(text) → {rows, extraLines}`, `serializeEnv(rows, extraLines)` — lossless round-trip for well-formed input, verbatim preservation otherwise) with vitest unit tests in web (add a minimal vitest setup for web if none exists; if that is disproportionate, put the pure parser in server/src/deploy/envparse.ts and import from web — decide and note it).
**Tests:** parser round-trip incl. quotes/#/=/export/blank/comment lines; duplicate detection; masking rule.
**Gate:** parser tests + build/typecheck; screenshots of both modes, both themes.

### Task 7: Wire invites through email (spec §3 "What uses instance mail")
**Files:** server/src/routes/users.ts (invite + reinvite: when `isMailConfigured`, send the invite link by email; response gains `emailed: boolean`; failures never block the invite — log + report `emailed:false`), server/src/services/mailer.ts (invite template: subject "You're invited to Shipway", text + minimal HTML with the absolute URL built from `base_domain` → `https://deploy.<base_domain>/invite/<token>`), web settings/Team.tsx (show "Invite emailed to <address>" when emailed, else keep the copy-link panel; always show the link).
**Tests:** emailed path with injected mailer; not-configured path unchanged; failure path still 201 with emailed:false; audit unchanged.
**Gate:** full suite; screenshot of both invite result states.

### Task 8: Final verification, docs, review
Full gates (3× suite), dev smoke of the new endpoints (mail test, teams/email channel create + test-send, verify states, cancel timing measured, DNS outcome), README + docs/server-setup.md updates (instance mail, Teams/email channels, DNS confirmation), spec drift sync, then the whole-branch review + fix wave, merge feat/v3 → main, push.

# Shipway Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Shipway — a fast, native-process deployment dashboard (Coolify replacement) for intcore's Ubuntu 24.04 testing server.

**Architecture:** Single Node.js/TypeScript monolith: Fastify 5 API + webhook receiver + WebSocket log streaming + in-process deploy queue, serving a React/Vite/Tailwind SPA. State in SQLite via Drizzle. All privileged system mutations go through a `SysOps` interface (real impl: `sudo shipway-sysops`; dev/test impls: sandboxed). Deploys are release folders + atomic `current` symlink.

**Tech Stack:** Node 22, TypeScript, Fastify 5 (`@fastify/websocket`, `@fastify/secure-session`, `@fastify/static`), zod, Drizzle ORM + better-sqlite3, execa, octokit, cloudflare, argon2, React 18, Vite, Tailwind CSS, wouter, TanStack Query, Vitest.

**Spec:** `docs/superpowers/specs/2026-08-23-shipway-design.md` (read it first — this plan argues from it).

## Global Constraints

- TypeScript strict mode everywhere; `npm run typecheck` must pass at every commit.
- All privileged operations ONLY via the `SysOps` interface — never raw `sudo` calls sprinkled in code.
- Slugs must match `^[a-z0-9]([a-z0-9-]{0,38}[a-z0-9])?$` before touching any path/unit/config.
- Secrets (env blobs, SMTP/DB passwords) encrypted with `SecretBox` (AES-256-GCM) before hitting SQLite.
- Unit/vhost/file names on the system are always prefixed `shipway-`.
- A failed deploy must never leave a project's site broken (fail before activate ⇒ delete release; fail after ⇒ rollback).
- Monorepo: npm workspaces `server/`, `web/`. Tests run on macOS dev machine without root.
- Commit after every green task with a conventional-commit message.

Template requirements (assert via string matching in tests):
- All vhosts: `listen 443 ssl; http2 on;`, `server_name <domain>;`, `ssl_certificate /etc/letsencrypt/live/<certName>/fullchain.pem;` + key, port-80 server block with `return 301 https://$host$request_uri;`, `client_max_body_size 100m;`.
- php: `root <appsDir>/<slug>/current/<publicDir>;`, `index index.php`, `try_files $uri $uri/ /index.php?$query_string;`, `fastcgi_pass unix:/run/php/php<phpVersion>-fpm.sock;` inside `location ~ \.php$`.
- node/nextjs: `location / { proxy_pass http://127.0.0.1:<port>; }` with `proxy_set_header Upgrade $http_upgrade; proxy_set_header Connection "upgrade"; proxy_set_header Host $host; proxy_http_version 1.1;`.
- static: `root …/current/<publicDir>;`, `try_files $uri $uri/ /index.html;`.
- App unit: `[Service] User=deployer`, `WorkingDirectory=<appsDir>/<slug>/current`, `Environment=PORT=<port>`, `EnvironmentFile=-<appsDir>/<slug>/shared/.env`, `ExecStart=/bin/bash -lc 'export PATH=<nodeBin>:$PATH && exec <startCmd>'`, `Restart=always`, `RestartSec=3`, `[Install] WantedBy=multi-user.target`.
- Worker unit: same shape, `ExecStart=/bin/bash -lc 'export PATH=<pathPrefix>:$PATH && exec <command>'`.
- Crontab line format: `<schedule> cd <appsDir>/<slug>/current && <command> >> <logsDir>/<slug>/cron-<id>.log 2>&1`.
- `assertSlug` throws on `''`, `'UPPER'`, `'a b'`, `'-x'`, 41+ chars.

- [ ] Steps: failing tests asserting each requirement above (one test per template kind + slug + mergeCrontab preserving unrelated user cron lines) → implement as template-literal functions → PASS → commit `feat: nginx/systemd/crontab templates`.
